# Semantic model

The semantic model defines the terms and relationships needed to interpret a
project's engineering knowledge. A concept definition gives a term an identifiable
meaning and scope. A reference to that concept must not silently change its meaning.

Projects may need concepts such as components, interfaces, constraints, capabilities,
or quality attributes. These are candidate domain categories, not a compulsory
checklist. Include a category only when the domain needs it.

Distinguish a concept's definition from instances and statements about instances.
Changes to a definition must preserve the ability to interpret historical artifacts.
Record deprecation, replacement, and affected uses rather than silently assigning
new meaning to an existing identity.

The concrete identifier scheme and extension mechanism remain unspecified in this
initial revision. No ontology serialization or automated reasoning capability is
claimed.
